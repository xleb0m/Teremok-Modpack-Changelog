### Branches

- **`main`** — the stable branch. This is the build our testing team plays on. Only finished, tester-facing content lives here — development/debug tools used while building the pack are excluded.
- **`dev`** — the maintainer's active working branch. Contains everything in `main` plus in-progress work and dev-only tooling (debug/profiling mods, structure generators, etc.) that never ships to `main`.

When a batch of changes is considered stable enough for the testing team, it gets merged from `dev` into `main` and tagged as a release (e.g. `s2-pre-alpha.0.1.0+build.1`). The `CHANGELOG.md` entry for that release only lists what actually changed for testers — dev-only tooling changes are not included, since testers never see them.

### Versioning

The pack follows a custom versioning scheme suited to a testers-only, multi-stage build cycle:

```
s<season>-<stage>.<major>.<minor>.<patch>+build.<N>
```

| Part | Meaning |
|------|---------|
| `s<season>` | Season number, fixed for the pack's whole lifecycle |
| `<stage>` | Current readiness stage: `pre-alpha` → `alpha` → `pre-beta` → `beta` → `pre-release` → `release` |
| `major.minor.patch` | Resets with each new stage. `major` = structural overhaul, `minor` = mods added/removed or new bridges, `patch` = balance/config/bugfixes |
| `+build.<N>` | Sequential build counter, incremented by exactly 1 on every release regardless of what changed |

Example progression:
```
s2-pre-alpha.0.1.0+build.1
s2-pre-alpha.0.1.1+build.2   <- balance patch
s2-pre-alpha.0.2.0+build.3   <- new mod added
s2-alpha.1.0.0+build.4        <- stage promoted to alpha
```

Full release history with dates lives in [CHANGELOG.md](./CHANGELOG.md).

### How this repository is maintained

The mod list and changelog entries for new/updated mods are generated by an internal script (not included in this repo) that only the pack maintainer runs locally against their own `mods/` folder. This is intentional: if multiple people ran it independently, differences between local setups (partially updated folders, test mods, different mod loader states) would create conflicting or duplicate entries in the mod list.

**If you're contributing to this repo:**
- Feel free to edit `CHANGELOG.md` by hand for anything that isn't a plain mod add/update (bridge recipes, config balance changes, bugfixes, removed mods) — just follow the existing [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format.
- Please don't regenerate `modlist.md` / `modlist/*.md` / this README's category table yourself — leave mod list updates to the maintainer to avoid merge conflicts and duplicate entries.
- If you spot a wrong category or a missing mod, open an issue or ping the maintainer instead of editing the generated files directly.

### Ветки

- **`main`** — стабильная ветка. Именно на этой сборке играет наш тестерский отдел. Здесь находится только готовый, предназначенный для тестеров контент — инструменты для разработки/отладки, используемые в процессе сборки, сюда не входят.
- **`dev`** — рабочая ветка мейнтейнера. Содержит всё то же, что и `main`, плюс незавершённые наработки и dev-инструменты (моды для дебага/профилирования, генераторы структур и т.д.), которые никогда не попадают в `main`.

Когда набор изменений считается достаточно стабильным для тестерского отдела, он вливается из `dev` в `main` и помечается тегом релиза (например, `s2-pre-alpha.0.1.0+build.1`). Запись в `CHANGELOG.md` для этого релиза содержит только то, что реально изменилось для тестеров — изменения dev-инструментов туда не попадают, так как тестеры их никогда не видят.

### Версионирование

Сборка использует собственную схему версионирования, подходящую под многостадийный цикл разработки только для тестеров:

```
s<сезон>-<стадия>.<major>.<minor>.<patch>+build.<N>
```

| Часть | Значение |
|-------|----------|
| `s<сезон>` | Номер сезона, фиксирован на весь жизненный цикл сборки |
| `<стадия>` | Текущая стадия готовности: `pre-alpha` → `alpha` → `pre-beta` → `beta` → `pre-release` → `release` |
| `major.minor.patch` | Обнуляется при смене стадии. `major` = структурная переработка, `minor` = добавлены/убраны моды или новые мосты, `patch` = баланс/конфиги/багфиксы |
| `+build.<N>` | Сквозной счётчик билдов, увеличивается ровно на 1 при каждом релизе, независимо от того, что изменилось |

Пример прогрессии:
```
s2-pre-alpha.0.1.0+build.1
s2-pre-alpha.0.1.1+build.2   <- патч баланса
s2-pre-alpha.0.2.0+build.3   <- добавлен новый мод
s2-alpha.1.0.0+build.4        <- переход на стадию alpha
```

Полная история релизов с датами — в [CHANGELOG.md](./CHANGELOG.md).

### Как ведётся этот репозиторий

Список модов и записи о новых/обновлённых модах в чейнджлоге генерируются внутренним скриптом (не входит в этот репозиторий), который запускает только мейнтейнер сборки локально, на своей собственной папке `mods/`. Это осознанное решение: если бы скрипт запускали несколько человек независимо, различия между локальными окружениями (частично обновлённые папки, тестовые моды, разное состояние модлоадера) привели бы к конфликтующим или задублированным записям в списке модов.

**Если вы хотите внести вклад в репозиторий:**
- Смело редактируйте `CHANGELOG.md` руками для всего, что не является простым добавлением/обновлением мода (рецепты мостов, балансные правки конфигов, исправления багов, удалённые моды) — просто придерживайтесь существующего формата [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
- Пожалуйста, не перегенерируйте `modlist.md` / `modlist/*.md` / таблицу категорий в этом README самостоятельно — обновление списка модов оставьте мейнтейнеру, чтобы избежать конфликтов при слиянии и дублирующихся записей.
- Если заметили неверную категорию или отсутствующий мод — заведите issue или напишите мейнтейнеру, а не редактируйте сгенерированные файлы напрямую.
